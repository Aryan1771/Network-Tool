Detection Engine Configuration & Theoretical Bounds

A. Port Scan Detection (RULE-01-PORT-SCAN)

Triggers when a single source host addresses > {{ settings.port_scan_threshold_ports or 20 }} unique destination ports within {{ settings.port_scan_window_seconds or 10 }} seconds.

B. TCP SYN Flood Detection (RULE-02-SYN-FLOOD)

Triggers when incoming SYN traffic exceeds {{ settings.syn_flood_threshold_pps or 100 }} packets/second and the handshake completion ratio (ACK/SYN) remains below {{ (settings.syn_flood_ratio_threshold|float * 100)|round|int if settings.syn_flood_ratio_threshold else 10 }}%.
Academic Limitation Note: Incomplete PCAP traces without reverse path traffic will observe 0% handshakes; bidirectional monitoring is required for definitive estimation.

C. Brute-Force Login Detection (RULE-03-BRUTE-FORCE)

Triggers when repeated connection attempts exceed {{ settings.brute_force_threshold_attempts or 10 }} times within {{ settings.brute_force_window_seconds or 60 }} seconds to monitored service ports (21, 22, 23, 80, 443, 3389).
Clarification: Monitors connection requests at the transport layer; credential verification requires application authentication logs.

D. Data Exfiltration Detection (RULE-04-DATA-EXFILTRATION)

Triggers when total outbound data volume from an internal host to an external target exceeds {{ settings.data_exfil_multiplier or 5.0 }}x the baseline volume within {{ settings.data_exfil_window_seconds or 300 }} seconds.
